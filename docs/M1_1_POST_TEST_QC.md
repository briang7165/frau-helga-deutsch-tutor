# M1.1 post-review changes — Compact Classroom and Teacher Feedback

**Status:** user requested post-test improvements on November 8, 2026; PR #3 remains **open**. Continue work on **existing branch** `feature/m1-1-learning-ux`, DO NOT merge. This change request is a local-offline UX corrective pass, not authorization for Gemini, ElevenLabs, Cloudflare, billing or Gmail.

## User findings (two Firefox screenshots)
- On a split-screen Windows desktop Firefox viewport (~1100x550–700 available), layout wastes space in a 230px left sidebar and 230px “Frau Helga’s Desk” rail; excessive header, progress stats, padding and large lesson card force scrolling to see answer + feedback + next action. User wants most lesson steps complete without page-level scroll, including after feedback.
- Reading activity r1 asks `Wohin fährt Nora am Samstag?` (where Nora travels Saturday) and says answer in German, but learner typed an English translation of the entire paragraph: `On Saturday Nora goes by train to Bonn. She visits her brother. At night she goes to the Rhein Space.` Current feedback merely `Needs review — unscored`. The app should identify real evidence of comprehension (Bonn, train, brother), note task mismatch (question requires short destination answer in German), and explain meaning errors: `Am Nachmittag` = afternoon (NOT at night); `gehen sie am Rhein spazieren` = they go for a walk by the Rhine (NOT 'Rhein Space'). This is **NOT** a fully correct answer to the original question. Award earned partial credit only when objective and rubric can reliably support it, not for unrelated verbosity.
- User hears no game effects or German speech, and records voice but cannot receive transcription or speech grading. Code review: settings defaults `sfx:false`, `muted:true`; browser speech voices must exist and be selected/allowed; current `MicrophoneControls` records for diagnostic/replay but no `transcribe` integration; do not imply otherwise.

## A. Compact classroom design — priority 1
1. Use responsive desktop layout with **collapsible sidebar** (icon rail when collapsed, optional expanded overlay) and optional/compact Frau Helga help drawer. In split-screen mode the content gets nearly all width; teacher personality remains available via small contextual bubble or avatar button.
2. Keep one compact top strip containing section title, 6-step progress, timer, settings/voice/sfx controls; eliminate repeated progress blocks and large greeting/stats in active lesson view. Dashboard can retain richer view.
3. Place directions immediately before task in short **one- or two-line English** format with a clear expected answer language and skill; a `More instructions` expander holds the explanatory policy text.
4. Use readable 14–18px typography, 8–14px gaps, compact source passage, short input by default (one line for destination, 2–3 for writing, expandable when typing), an obvious single primary action. Do not shrink below accessible readable limits to meet fit.
5. Feedback should render as compact inline panel beneath question or beside answer, with short `What you got right`, `Correction`, `Next step`; accordion for detailed rubric. Action rail `Check / Try again / Continue` stays visible/sticky near bottom of lesson container. After grading, no large layout jump or forced page scroll; auto-focus/accessibly announce feedback; content must remain reachable with keyboard, zoom and reduced-motion preferences.
6. Target viewport tests: **1280x720**, **1100x650**, **1366x768**, **1920x1080**; 390px mobile must remain usable, and 200% zoom must not hide content. Normal short task with compact feedback should fit without document-level vertical scroll at 1100x650 where feasible; allow internal panel scroll for expanded details and accessibility. Do NOT globally suppress overflow or clip content.
7. Persist compact/comfortable display preference and sidebar collapsed state; changing layout should not reset lesson or answers.

## B. Meaningful feedback for answer intent — priority 2
1. Extend Activity metadata with **task intent** (destination question, translation, comprehension, writing, etc.), **expected language**, **short answer target**, explicit rubric and reference facts. Show short plain-language guidance (e.g. `Where does Nora travel? Answer in German with a place, not a translation of the paragraph.`).
2. For bounded offline r1, write a transparent, conservative intent-aware evaluator using known fact/rubric patterns, not mere substring matching. Understand `nach Bonn`, `Bonn`, `Sie fährt nach Bonn`, and common English phrase `Nora goes/travels to Bonn` with language penalty, without accepting contradictions such as `Nora does NOT go to Bonn`, `not Bonn`, etc.
3. Specifically handle a longer mostly English paraphrase/translation of the provided r1 passage: recognize destination and facts it actually states, flag that it answered a different task and in the wrong language, and provide the target answer. If optional feedback on unrelated translation is supported, explain `Am Nachmittag` vs `at night` and `gehen sie spazieren` vs `Rhein Space`. Avoid pretending to evaluate unlimited translations; use bounded known facts or `needs_review` for uncertain cases.
4. Provide actual rubric: destination comprehension (60), response language (25), answering the asked question (15), or another well-explained balanced rubric. English response that clearly identifies Bonn may earn partial credit; German `Nach Bonn` earns full credit. Correct `Bonn` alone earns full credit as a language-neutral proper noun. Incorrect destination cannot earn most points.
5. Separate **task compliance** from general language skill. If unsure, state `I can see that you mention Bonn, but cannot confidently grade the entire sentence offline` and mark unscored for uncertain parts rather than fake grading. No arbitrary positive feedback based on a keyword in a negative/irrelevant clause.
6. Every feedback result offers a clear corrective sentence and a **Continue** option; user can choose `Try again` for practice, without unfair grade replacement (first-attempt preserved). No need to hunt for `Section review`.
7. Add tests for exact user example, German correct forms, short English destination, English translation with correct destination + wrong time phrase, contradictory mentions of Bonn, wrong city, language preference, "Nach Bonn" capitalization and punctuation, skip, and uncertain inputs.

## C. Sound and voice diagnostics — priority 3
1. Keep safety/privacy default off for sound if desired, but on initial classroom UI show a brief clickable `Enable gentle sounds` prompt, with mute icon, volume slider/test. Sound should work after explicit user gesture, indicate if Web Audio is suspended and resume context on click; volume settings and mute persist.
2. In Voice & Microphone settings, show `No German voice found`, available voices and language tags, explicit `Test voice` button, OS/browser setup tips and `Test speaker` using original UI synth tone where possible. Never claim generated Frau Helga voice exists when it doesn't.
3. Add a first-run **audio setup check** that clearly separates: `Sound effects`, `Voice output`, `Microphone input`, `Speech recognition`, each with states Available / Off / Unavailable / Not connected, and CTA. In lessons show `Recorded locally—NOT transcribed or graded` immediately next to record action, with `Replay` and `Discard` where supported; don't require user to discover limitations after recording.
4. Preserve local audio privacy (in-memory only, no auto upload); no calls to third-party endpoints during M1.1.

## D. Reduction of friction — priority 4
1. Standard primary sequence `Answer → Check → useful concise feedback → Continue`, clear keyboard shortcuts (e.g. Ctrl+Enter submit, Enter next only when appropriate) with clear disabled/skip behavior and focus management.
2. Auto-save typed draft per current activity **only in memory** (persisting draft opt-in; default no raw text persistence). Navigating help and settings should preserve answer for active session; pause/resume safe.
3. Allow `Skip for now`, `Explain the question`, `Show a hint` without complicated modal stacks. After initial response, prioritize corrective feedback over rubric tables or multiple paragraphs.
4. User-friendly first-run intro: `6 activities · approx 30 min · no real speech grading yet`, sound check; avoid technical boilerplate during each exercise.
5. Track useful UX measures only locally (completion, time-to-next, skip rate), never expose private lesson content.

## E. Clearly scoped future speech/AI milestone — NOT in this corrective pass
1. Meaningful free-form grading requires a server-side semantic evaluator. Plan an **optional** Gemini free-tier provider using JSON schema validation with fields for task-fit, factual correctness, grammar, explanation, rubric and confidence. Apply local checks / verification so the model cannot arbitrarily reward wrong answers; disclose API cost/privacy and allow opt-in. Never put API key in Vite `VITE_` variables or a public repo.
2. Real voice recognition requires explicit upload consent and a server-side transcription path (Gemini speech-to-text); store audio nowhere by default. Distinguish transcription confidence from pronunciation scoring, which needs separate valid assessment.
3. Frau Helga's human-quality older German voice can use Gemini TTS free-tier as a first test or optional ElevenLabs; verify latency/quotas/voice and licensing, user consent, and cost. No external voice API now.
4. Existing user budget preference **$0 preferred, $5/month ceiling**; no activation/paid upgrade without separate permission. Free-tier Gemini traffic may be used for model improvement; disclose it before enabling personal speech data transfer.
